# Instalación de los SO

Por cada SO se ha instalado y configurado los parámetros tanto de la red como de sus servicios. Además, se tiene en cuenta que por cada sistema instalado se ha apuntado la contraseña y el usuario para una mayor gestión.

---

## Sistemas de Enrutamiento y Seguridad

### MikroTik
Para la instalación del MikroTik se ha descargado de la página oficial de MikroTik un VDI, es decir un disco virtual, que contiene en su interior el SO RouterOS.

Para configurar la red, como el MikroTik tiene que tener salida a internet, se le han puesto dos interfaces: la NAT y la red interna. La NAT es la exterior a internet y la red interna es la LAN. Se realiza un `/ip address add` para añadir la IP de la LAN directamente a la interfaz `ether2` con la IP `41.1`, ya que en la NAT la IP es por DHCP.

### OPNsense
Para la instalación del OPNsense, igual que al MikroTik, se le han asignado dos interfaces: la NAT y la red interna.

| Concepto | Detalle de Configuración |
| :--- | :--- |
| **Instalación** | Se ha puesto la ISO de OPNsense, asignando durante la instalación cuál es la WAN y cuál la LAN. |
| **Asignación de IP** | La WAN se hace por vía DHCP y la LAN es estática con la `41.2`. |
| **Persistencia** | Al ponerlo como un live CD la configuración no se guarda al reiniciar la máquina, entonces se tiene que loguear con un usuario llamado `Installer` sin contraseña. Al iniciarse te carga el instalador donde ya te pide un disco donde descargar e instalar los datos del SO. Cuando ya acaba el proceso se inicia automáticamente y no se pierden los datos hechos anteriormente. |

### ServerCom
Para la instalación del ServerCom, como en los otros dos anteriores, se le han asignado dos interfaces: la NAT y la red interna.

- **Instalación:** La instalación es la normal, como si fuera un Debian normal, pero como tiene que ser sin interfaz gráfica, en el apartado de seleccionar una interfaz se desmarca la interfaz seleccionada y entenderá que es sin interfaz.
- **Configuración SNAT:** Al ser un servidor de comunicaciones y todo el tráfico pasa por este, tenemos que hacer un SNAT para permitir que los equipos puedan salir fuera de la red. Para ello se crea una tabla con `nftables` con `masquerade`, asignando la interfaz de la WAN para poder esta salida.

## Almacenamiento y Pruebas

### TrueNAS
Para la instalación del TrueNAS se ha asignado una sola interfaz, que es la red interna. Se ha puesto la ISO de TrueNAS, haciendo que internet vaya por su única interfaz de red.

Como es el servidor de copias de seguridad, se ha añadido un VDI extra de 1TB (igual que en clase) para las copias de los sistemas de la red. Para ello se ha entrado por interfaz gráfica y se ha añadido el disco como *stripe*. Al añadirlo se ha creado un pool dentro del disco, llamado `Copia_Seguridad`. Y dentro de él se han creado subpools ya de cada sistema, por ejemplo `backup_debian`.

### Debian_Pruebas
- **Red e ISO:** Se ha asignado solo la interfaz de red interna con la LAN. Se ha puesto la ISO de Debian 13.
- **Propósito:** Este es un Debian simple, solo para entrar en las interfaces de los servidores y comprobar conectividad entre las máquinas.

## Virtualización y Servidores de Dominio

### Proxmox 1, 2 y 3

| Aspecto | Detalles de Configuración |
| :--- | :--- |
| **Red e ISO** | Se ha asignado una sola interfaz con la red interna LAN. Se ha puesto la ISO de Proxmox. |
| **Correo** | En la instalación te piden un correo para enviar mensajes al correo para fallos, en mi caso se ha puesto uno falso. |
| **Diferencias e IPs** | Las tres máquinas son exactamente iguales, lo que cambia es la IP y el hostname.<br>- **IP:** Hay que ir a `/etc/network/interfaces` y cambiar la IP por la que necesites (en mi caso son las `.10`, `.11` y `.12`).<br>- **Hostname:** Hay que entrar en `/etc/hostname` y en `/etc/hosts` y poner en los dos el mismo hostname. |
| **Clúster** | Ya creados los tres Proxmox y comprobar que funcionan, hay que crear el clúster. Se ha elegido un nodo y creado el clúster uniendo el resto de los nodos con el código del clúster. Haciendo que cuando entres a cualquiera de los tres puedes configurar cualquiera de los tres. |
| **WinServer2025 Interno** | Este Proxmox tiene virtualizado en su interior el WinServer2025 con un VDI de 100GB solo para el server. Pero por problemas de virtualizado el WinServer está simulado y no funciona en Proxmox, está fuera del Proxmox. |

### WinServer2025
Para la instalación del WinServer2025 se ha asignado una sola interfaz con la red interna LAN y la ISO de Windows Server 2025.

- En esta instalación se ha elegido la versión estándar de versión escritorio del server, es una instalación normal de Windows. 
- Después de la instalación se han puesto las características de Active Directory, es decir el dominio, para la gestión de los clientes con sus pasos correspondientes. 
- Además de crear los usuarios del dominio para poder loguearse en los clientes (en mi caso es Cliente1-6). 
- El dominio en mi caso se llama `GRUPO4.local`.

## Clientes

### WinClientes (1, 2 y 3)
Es un Windows 11 normal con solo la interfaz de la red interna LAN. Pero para unirlos al dominio hay que poner como DNS la IP del server, y ya después de eso lo unes al dominio con las credenciales registradas del WinServer2025. Ya unidos al dominio iniciamos sesión con los usuarios creados anteriormente y que se cree el perfil.

### DebianCliente
Para el DebianCliente es un Debian 13 con la interfaz de la red interna LAN. Es una instalación normal hasta que llegas a unir al dominio, hay que instalar unos controladores para permitir unir al dominio, que son `realmd`, `SSSD` y `Kerberos`. Ya unido al dominio, para iniciar la sesión hay que hacerlo con `usuario/grupo4.local`.

### Dual Boot
Es la combinación de los dos SO juntos, es decir es un disco particionado con un Debian 13 y un Windows 11. La interfaz es la red interna LAN.
